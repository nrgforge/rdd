## Summary

Implements code review as a utility skill (/rdd-review) rather than a pipeline phase, since review must happen at variable granularity during build and the standalone MR-review use case has no pipeline context at all. It can be invoked at any time from any context, does not produce a phase artifact or gate pipeline progression, and integrates with build stewardship checks as an optional enhancement without replacing them; its output (questions for the reviewer's consideration) is deliberately ephemeral, since the success criterion is whether the reviewer can discuss the change with informed judgment, not whether a review record exists.
