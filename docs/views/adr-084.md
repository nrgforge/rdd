# ADR-084: Agent-Context Content Placement — Companion File or Audience-Tagging, Not Directory Separation

[← Overview](overview.md)

**Type:** ADR (index) · **Status:** Proposed · **Cycle:** 017 · **Canonical source:** `docs/decisions/adr-084-agent-context-content-placement.md`

**Workflow point:** ARCHITECT restructuring of Tier-2 readables (e.g. system-design.md) · **Mechanism:** Pattern A (audience-tagged sections) or Pattern B (<artifact>.agents.md companion file), chosen per-artifact by a felt content-divergence threshold

## Summary

The methodology adopts per-artifact judgment between two patterns for agent-context content placement, with directory-level audience separation (e.g. `docs/agent/`) rejected. Pattern A (audience-tagged sections within the existing artifact) applies where human-facing and agent-facing material present the same facts differently; Pattern B (a companion file at a predictable path, `<artifact>.md` → `<artifact>.agents.md`) applies where the content is functionally divergent, with the felt threshold being whether audience-tagged volume would exceed roughly 50% of the human-facing baseline. `system-design.md` is the cycle's exemplary Pattern B case: the diagram and an F-pattern orientation lead stay in the human-facing file, and agent-context detail (driver table, fitness criteria, responsibility allocations, provenance chains) moves to `system-design.agents.md`.
